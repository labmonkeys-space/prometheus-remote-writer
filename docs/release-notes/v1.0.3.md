A fix for the queries that read the resource metadata series. If you copied a `group_left` join on `onms_resource_info` or `onms_resource_attr` from the documentation into a dashboard or an alert rule, replace it.

The plugin itself is unchanged: no configuration keys, no wire format, no on-disk format. Upgrading is a KAR swap, and the part that matters is the query change below.

## What was wrong

The documented join read the metadata series straight through the lookback, `… * on(resourceId) group_left(if_descr) last_over_time(onms_resource_info[30m])`. It fails with `found duplicate series for the match group` as soon as any one `resourceId` has two info series in the window (#241).

The failure is not limited to that resource. Prometheus and Mimir check the whole right-hand side for duplicates before they match, so one resource anywhere in the fleet fails every join that is not scoped away from it. Two things produce such a resource:

- **A changed value**, such as an `ifAlias` rename. Both series stay in the window for up to 30 minutes.
- **Two OpenNMS objects on one `resourceId`**, which never heals. Stock Horizon 36 has one: its `telemetryAdapters` resource type puts `SFlow-Telemetry` and `SFlow-Adapter` on one resource, so any stack that processes sFlow carries a permanent duplicate.

An alert rule that joins this way errors instead of evaluating, which is a silent loss of coverage.

## What to write instead

Keep the newest series per resource before the join:

```promql
rate(ifHCInOctets[5m]) * 8
  * on(resourceId) group_left(if_alias, if_descr)
    group by (resourceId, if_alias, if_descr) (
      topk by (resourceId) (1,
        timestamp(onms_resource_info)
          or max_over_time(timestamp(onms_resource_info)[30m:1m]))
    )
```

For a single attribute, use the same shape on `onms_resource_attr{key="…"}` with `group by (resourceId, value)`. Keep `timestamp()` directly on the selector: VictoriaMetrics returns nothing for `timestamp()` over an expression. The *Duplicate match during churn* section of the resource-metadata documentation explains each part, and the `@ end()` form for applying today's alias to old data.

The documentation, the e2e resource-metadata dashboard and the comments in the shipped `.cfg` now use this form. The smoke gates evaluate it on Prometheus, Mimir and VictoriaMetrics over a duplicate built in the query.
