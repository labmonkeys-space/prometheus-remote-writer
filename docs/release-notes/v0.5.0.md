This release bounds default label cardinality, adds two new ways to authenticate, and makes the write pipeline parallelizable. Two changes are breaking, and both have a short migration.

## Highlights

**Bounded label schema by default** (#112). Emission is now a curated, fixed-size label set of roughly 15 names regardless of deployment size. The per-resource attribute round-trip (`onms_attr_*` / `onms_extattr_*`) is off by default: on a real deployment it produced 5,646 distinct label names against a comparable plugin's 8, with measurable backend memory and index cost. Every smoke run now asserts the backend's distinct label-name count stays under a bound, so an explosion cannot regress silently.

**Custom `Authorization` schemes** (#56). Backends and gateways that authenticate with a non-standard keyword had no configuration path at all. `auth.bearer.token` emits only `Bearer`, and `http.headers.Authorization` is reserved.

```properties
auth.authorization.type        = Token
auth.authorization.credentials = ${env:PROM_TOKEN}
```

Both keys are required together and there is no default scheme, so a typo cannot silently downgrade the request to `Bearer`. The scheme keyword is emitted verbatim with no allowlist, since most backends this serves use an unregistered keyword. The header goes on the read path as well as the write path, because Zero-Trust gateways gate both.

**Arbitrary HTTP headers** (#53). One property per header, attached to every outbound request:

```properties
http.headers.cf-access-client-id     = ...
http.headers.cf-access-client-secret = ...
```

That reaches Cloudflare Access service tokens, vendor API keys, per-tenant routing headers and `User-Agent` overrides. Reserved names such as `Content-Type`, `Authorization` and `X-Scope-OrgID` are rejected by name and point at the key that owns them. An invalid header set leaves the plugin inert rather than unauthenticated: a typo'd gateway token can never become a silent unauthenticated write.

**Parallel write pipeline** (#115). `writer.shards` (default `1`, unchanged behavior) splits series across N shards by label-set hash. Each shard owns a queue slice and a flusher with at most one request in flight, so per-series sample order is preserved while shards flush in parallel. One slow batch now stalls only its own shard instead of the whole pipeline.

**Secrets can stay out of the configuration file** (#55). Karaf resolves `${env:NAME}` in every configuration value, and `$[secret:name]` reads a value from a file. Both are verified on Horizon 36.0.3 with no container changes. Earlier documentation claimed the opposite and was wrong. The e2e suite now feeds its token through `${env:SMOKE_TOKEN}`, so this is a CI gate rather than a claim in prose.

## Breaking changes

### Default label emission changed

`onms_attr_*` and `onms_extattr_*` are no longer emitted by default, and metatag aliases of built-in labels now emit once (snake_case built-in only). Dashboards, recording rules and alerts referencing those labels need updating.

Migration, pick one:

- `labels.attr-mode = both` restores the full v0.4 emission.
- `labels.attr-mode = external` plus `labels.attr-include` restores graph placeholder substitution selectively.

See the Migration section of the docs.

### The auth-exclusivity startup error message was reworded

Adding a third mutually exclusive auth block changed the text logged when more than one is configured.

Was:

```
auth.basic.* and auth.bearer.token are mutually exclusive — configure one or neither, not both
```

Now, naming the blocks actually configured:

```
auth.basic.*, auth.bearer.token and auth.authorization.* are mutually exclusive — each one produces the Authorization header. Configured: auth.basic.* and auth.bearer.token. Keep exactly one of the three blocks, or none.
```

Migration: update any log-scraping alert or runbook matching the old string. The startup authentication line (`prometheus-remote-writer authentication: ...`) also changed shape. It no longer echoes any configured value, and it reports a mode only when the corresponding block is complete enough to actually produce a header, so it can no longer claim authentication the request builder would not send.

## Fixes

- `opennms:prometheus-writer-stats` was never registered and reported "Command not found" on every deployment (#113). The smoke gates now run it over Karaf SSH, and the new per-shard gauges reach operators through its table.
- The empty-value error under `http.headers.*` told operators secrets had to be literal cleartext, pointing away from the actual fix (#55). It now names both `${env:NAME}` and `$[secret:name]`.

## Also in this release

- `labels.profile` key (`native` default). The `legacy` profile, for drop-in series continuity when migrating from `opennms-prometheus-remotewrite-plugin`, is guarded until its fixture lands and fails with a clear message.
- Character validation on every operator-supplied value that reaches a request header raw (`auth.authorization.*`, `auth.bearer.token`, `tenant.org-id`): no CR/LF, no non-printable or non-ASCII bytes. Without it an illegal byte escaped the retry path and dropped every batch indefinitely while the plugin still reported healthy. Errors name the key and never echo the value.
- Docs: Grafana quickstart against the native schema, a Migration section, and troubleshooting entries for 401/403 and label-name explosions.

## Known limits

AWS SigV4, OAuth2, GCP IAM and Azure AD remain out of scope: they need a request signer, not a configuration value. There are no multi-value headers. For `auth.bearer.token` and `tenant.org-id`, an empty resolved value is indistinguishable from "disabled", so a typo'd variable name degrades silently to no credential. Karaf destroys the reference before the plugin sees it, so the plugin logs its effective authentication at startup instead.
