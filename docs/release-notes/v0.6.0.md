**This release raises the minimum supported OpenNMS Horizon to 36.0.4.** Horizon 35.x through 36.0.3 are no longer supported. Read the Breaking changes section before upgrading.

## Breaking changes

**Minimum OpenNMS Horizon moves from 35+ to 36.0.4+** (#139).

The plugin's Karaf feature requires `opennms-integration-api`, and it required it as a bare `2.0.0`. Karaf reads a bare version as the exact range `[2.0.0,2.0.0]`, so the KAR installed on exactly one API version and nothing else. Horizon 36.0.4 ships `opennms-integration-api` 2.0.1, and the KAR stopped installing on it entirely — the feature failed to resolve and the plugin never started.

The requirement is now the range `[2.0.1,3.0.0)`. A future Horizon shipping 2.0.2 or 2.1.0 will work without a plugin release; a 3.x API will fail cleanly at install time rather than at runtime.

The floor is 2.0.1 because that is the API this plugin is built and tested against. Horizon 35.0.x, 36.0.0, 36.0.1, 36.0.2 and 36.0.3 all ship 2.0.0 and will refuse to resolve the feature.

**Migration:**

- On Horizon **36.0.4 or newer** — upgrade normally, nothing to do.
- On Horizon **35.x–36.0.3** — either upgrade Horizon to 36.0.4+, or stay on plugin **v0.5.1**, which remains available and supports those versions.

If you install this release on an unsupported Horizon, the failure is visible and harmless: the feature does not resolve, `karaf.log` records `missing requirement ... osgi.identity=opennms-integration-api`, and no samples are written. Nothing is corrupted and the previous plugin version can be redeployed.

## Highlights

**The supported range is now proven, not asserted.** The smoke suite runs as a matrix over the oldest supported and newest released Horizon, so both ends of the declared compatibility range are exercised on every pull request. Previously the README claimed Horizon 35+ while no CI job ran against anything but a single pinned version.

**The three places that declare the API floor can no longer disagree.** The build property, the Karaf feature range and the bundle's `Import-Package` range are checked against each other by `make verify-compat` in CI. The 36.0.4 breakage happened because a dependency bump moved the build property to 2.0.1 and nothing noticed the feature still demanded 2.0.0 — that specific drift now fails the pull request.

**The bundle declares its own floor.** `Import-Package` for the Integration API timeseries packages is now an explicit `[2.0.1,3)` rather than a range computed from the compiled-against version. A bundle installed outside the KAR fails at install time on an unsupported API instead of wiring successfully and failing later at runtime.

## Upgrade notes

Check your Horizon version first:

```bash
docker exec <core-container> cat /opt/opennms/etc/version.properties 2>/dev/null \
  || rpm -q opennms-core
```

On 36.0.4+, drop in the new KAR as usual. On anything older, see Migration above.
