A correctness release for the disk overflow tier under `overflow.full = drop-oldest`, the mode an operator chooses for a long backend outage. No configuration keys, defaults, metric names, wire behaviour or on-disk formats change. Upgrading is a KAR swap.

## Highlights

**Evicting while draining no longer breaks the bucket's accounting or its reader** (#214, #215). A shard's append thread evicts segments under `drop-oldest` while the flusher's threads read and acknowledge from the same bucket. Four pieces of shared state were unguarded, and all four surfaced only in that mode:

- The checkpoint could be advanced by both sides at once. The loser threw "checkpoint cannot move backwards": a spurious WARN on the eviction side, and on the acknowledgement side an ERROR, a rewind and skipped counters for a batch the backend had taken (#215).
- `overflow_pending_samples` drifted. Appends and acknowledgements could lose each other's update, and an acknowledged segment that garbage collection had not removed yet, or a batch an eviction overtook in flight, was subtracted twice. The count is now atomic, an eviction and an acknowledgement decide under one lock which of them takes a frame off it, and the count re-bases to 0 whenever the bucket empties. It is an estimate while a bucket at its bound is being drained; the operations guide says where.
- An eviction on the append thread closed the reader the flusher was reading from. The reader now belongs to the flusher's threads under one lock, and an eviction only flags it for repositioning.
- Segment GC and eviction, which delete on different threads, could each fail with `NoSuchFileException` when the other removed the segment first.

## Fixes

- **`samples_dropped_wal_full_total` counted the frames of an evicted segment the flusher had already read into as 0.** Closing a segment opened for reading rewrote its index with a sample count of 0. A read-only segment no longer writes an index, so the counter and the pending count see every evicted frame (#220).
- Dependency updates: `slf4j-api` 2.0.19; the e2e stack moves to Alpine 3.24, Prometheus 3.14.0 and VictoriaMetrics 1.152.0.
